# Together Listen V2 测试策略

## 1. 目标

建立架构升级过程中的质量保障体系，确保功能迁移后保持现有同步听歌能力，并验证新增架构的稳定性。

## 2. 测试原则

- 保持核心功能行为一致；
- 每个迁移阶段均可独立验证；
- 优先保障实时同步稳定性；
- 测试规模以 2H2G 服务器和小规模用户场景为基准。

## 3. 功能测试

### 房间功能

验证：

- 创建房间；
- 加入房间；
- 离开房间；
- 多房间同时运行。

### 播放功能

验证：

- 播放；
- 暂停；
- 切换歌曲；
- 调整进度；
- 队列管理。

## 4. 实时同步测试

测试目标：

- 多客户端播放状态一致；
- 网络延迟情况下自动校准；
- 断线重新连接后恢复状态。

指标：

- 普通网络环境同步误差小于 200ms；
- 长时间播放无明显漂移。

## 5. 性能测试

基准环境：

- CPU：2核心；
- 内存：2GB；
- 在线用户：10人以内。

关注指标：

- CPU 使用率；
- 内存占用；
- Socket 连接稳定性；
- 消息延迟。

## 6. 发布检查

发布前确认：

- 原功能全部通过；
- 数据迁移成功；
- 部署脚本正常；
- 回滚方案可执行。
